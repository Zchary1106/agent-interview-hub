## 25. 写入工单的请求超时且结果未知时，如何恢复而不重复创建工单？

**题目 ID**：`Q-20b493aba9be` · **编辑难度**：`hard`

**相关主题的报道公司（非逐题归属）**：vivo

**参考答案**

把结果标为未知而非失败，使用稳定业务幂等键向外部系统查询或用同键重试。外部不支持去重/查询时进入人工对账或补偿流程，不能保证一次效果。

**得分点**

- 先持久化操作意图和关联 ID
- 区分网络失败与业务失败

**追问**：请求其实成功但本地还没存回执就崩溃了怎么办？

**易错点**：重新生成幂等键再重试会制造重复工单。

**面经主题线索**：[INT-4aea8e37ae](https://www.nowcoder.com/discuss/932565368587976704?sourceSSR=post)（B：曾定位公开原帖）

**答案机制资料**：[REPLAY：LangGraph Graph API: re-execution and idempotency](https://docs.langchain.com/oss/python/langgraph/graph-api)；[FENCE：How to do distributed locking, Martin Kleppmann](https://martin.kleppmann.com/2016/02/08/how-to-do-distributed-locking.html)

## 26. 请列出 Agent 服务重启后继续任务所必需的持久化字段。

**题目 ID**：`Q-a8212cd54d26` · **编辑难度**：`hard`

**相关主题的报道公司（非逐题归属）**：京东、字节跳动

**参考答案**

至少保存任务契约、输入/来源版本、当前步骤与状态版本、计划、工具意图/幂等键/回执、产物引用、审批和权限版本、重试预算、租约及错误。模型版本和关键配置也要可回溯。

**得分点**

- 敏感数据不无差别落盘
- 恢复时重新校验失效的审批及外部状态

**追问**：哪些内容可以重算，哪些必须落在提交前？

**易错点**：只存聊天记录不一定足以恢复外部业务状态。

## 27. 如何设计运行状态机，使不同步骤的进程崩溃都能落在明确恢复边界？

**题目 ID**：`Q-40978f8b0f9c` · **编辑难度**：`hard`

**相关主题的报道公司（非逐题归属）**：vivo

**参考答案**

把排队、运行、待确认、结果未知、成功、失败和取消等状态及允许转换显式化；每步先记录意图，再执行，再提交回执。跨外部系统的提交空隙必须通过查询、幂等或补偿处理。

**得分点**

- 用版本条件更新状态
- 按崩溃点注入故障验证恢复

**追问**：在哪些边界不能自动恢复？

**易错点**：状态机图画得完整，不代表跨系统原子提交已经解决。

## 28. Worker 持有的任务租约过期后，系统怎样避免旧 Worker 继续提交结果？

**题目 ID**：`Q-4ca045e6ed69` · **编辑难度**：`hard`

**相关主题的报道公司（非逐题归属）**：快手

**参考答案**

租约到期只表示新 Worker 可以接管，不会让旧进程自动停止。为每次所有权发放递增 epoch/token，资源写入端拒绝旧 epoch；旧 Worker 续租失败也应主动停止。

**得分点**

- 所有权与写入校验相连
- 覆盖长 GC 暂停、网络分区和时钟问题

**追问**：外部 API 不接受 token 时还能保证什么？

**易错点**：不能只依赖 Worker 自觉检查锁是否仍存在。

**面经主题线索**：[INT-065b4318d8](https://www.nowcoder.com/discuss/932315325276618752?sourceSSR=post)（B：曾定位公开原帖）

**答案机制资料**：[FENCE：How to do distributed locking, Martin Kleppmann](https://martin.kleppmann.com/2016/02/08/how-to-do-distributed-locking.html)

## 29. 怎样把 fencing token 用到存储写入校验，而不只停留在抢锁成功？

**题目 ID**：`Q-19a25978b3e3` · **编辑难度**：`hard`

**相关主题的报道公司（非逐题归属）**：快手

**参考答案**

下游原子保存已见的最大 token，并拒绝小于它的写入；相同 token 内再用操作 ID 与步骤版本保证幂等及顺序。token 必须来自可靠的单调所有权序列。

**得分点**

- 检查和写入不可分离
- 没有下游支持时明确保证边界

**追问**：较新的 Worker 暂时还没有写入，下游知道租约已失效吗？

**易错点**：token 不是对所有外部系统都自动生效的万能锁。

**面经主题线索**：[INT-065b4318d8](https://www.nowcoder.com/discuss/932315325276618752?sourceSSR=post)（B：曾定位公开原帖）

**答案机制资料**：[FENCE：How to do distributed locking, Martin Kleppmann](https://martin.kleppmann.com/2016/02/08/how-to-do-distributed-locking.html)

## 30. 两个 Worker 的结果先后写入并相互覆盖时，如何定位并防止状态回退？

**题目 ID**：`Q-4a11edd3ff54` · **编辑难度**：`hard`

**相关主题的报道公司（非逐题归属）**：快手

**参考答案**

先用 trace、owner epoch、状态版本和操作 ID 还原写入顺序；提交时用比较并交换或事务条件更新，只接受预期版本与合法转换。冲突者重读后重规划，不覆盖新状态。

**得分点**

- 终态不可随意回退
- 同 epoch 内也要检查版本

**追问**：两个结果都部分有效时如何合并？

**易错点**：最后写入获胜可能让旧结论覆盖新结论。

**面经主题线索**：[INT-065b4318d8](https://www.nowcoder.com/discuss/932315325276618752?sourceSSR=post)（B：曾定位公开原帖）

**参考答案**

## 32. 为什么有分布式锁也不必然保证多 Agent 的业务状态正确？

**题目 ID**：`Q-8f8d8ae8a429` · **编辑难度**：`hard`

**相关主题的报道公司（非逐题归属）**：vivo

**参考答案**

锁不保护已发出的外部请求，也未必防止过期持有者继续写；它还不能发现状态前提过时、业务不变量被破坏或重复操作。需组合 fencing、版本条件、幂等和业务校验。

**得分点**

- 区分互斥、所有权与业务正确性
- 说明多资源事务边界

**追问**：为什么锁还没到期也可能业务写错？

**易错点**：有锁不等于数据一定正确，更不等于任务完成。

**面经主题线索**：[INT-4aea8e37ae](https://www.nowcoder.com/discuss/932565368587976704?sourceSSR=post)（B：曾定位公开原帖）

**答案机制资料**：[FENCE：How to do distributed locking, Martin Kleppmann](https://martin.kleppmann.com/2016/02/08/how-to-do-distributed-locking.html)

## 33. 超时、取消与重试如何配合，避免用户取消后工具仍继续产生副作用？

**题目 ID**：`Q-7b11155eadb0` · **编辑难度**：`hard`

**相关主题的报道公司（非逐题归属）**：字节跳动、海康威视

**参考答案**

设置任务截止时间和每次调用预算；收到取消后停止调度新动作、传播取消并持久化取消意图。已经发出的写操作可能无法中止，仍须查询结果或补偿，不能仅返回“已取消”。

**得分点**

- 取消与提交处理竞争
- 重试必须服从取消标记

**追问**：工具不支持取消时如何向用户解释？

**易错点**：取消本地协程不等于外部动作被撤销。

**面经主题线索**：[INT-2bfa666e65](https://www.nowcoder.com/discuss/939623386806751232?sourceSSR=post)（B：曾定位公开原帖）；[INT-e363eb73e2](https://www.nowcoder.com/discuss/940356350117228544?sourceSSR=post)（B：曾定位公开原帖）

## 34. 中断恢复后怎样防止重复执行已经完成的步骤？

**题目 ID**：`Q-f20dc454c2c5` · **编辑难度**：`hard`

**相关主题的报道公司（非逐题归属）**：快手

**参考答案**

为步骤和外部操作保存稳定 ID、输入指纹、完成回执与产物版本；恢复先读取已有结果，只对可安全重放的部分重跑。LangGraph 可能重新执行节点函数，因此副作用仍需幂等封装。

**得分点**

- 恢复前确认外部状态
- 动态代码版本变化需迁移检查

**追问**：一个节点内包含两个写操作时怎么办？

**易错点**：checkpoint 不是对节点内部任意语句的事务快照。

**面经主题线索**：[INT-bbcb367aed](https://www.nowcoder.com/discuss/938541475766206464?sourceSSR=post)（B：曾定位公开原帖）

## 35. Agent 在失败路径之间反复切换时，怎样识别震荡并收敛到可恢复状态？

**题目 ID**：`Q-6cdf69b480cf` · **编辑难度**：`hard`

**相关主题的报道公司（非逐题归属）**：字节跳动

**参考答案**

记录动作类型、归一化参数、错误类型与状态进展指纹，检测有限窗口内重复且无收益的模式。触发后限制重试、换策略或转人工，并把失败证据带入恢复上下文。

**得分点**

- 分别限制步数、重规划次数和预算
- 保留诊断链

**追问**：重复动作有时是合理轮询，怎样避免误杀？

**易错点**：仅降低温度不能保证消除循环。

## 36. 跨越很长执行周期后出现目标漂移，你会记录和比较哪些证据？

**题目 ID**：`Q-0ca09e9165fa` · **编辑难度**：`hard`

**相关主题的报道公司（非逐题归属）**：字节跳动、小米

**参考答案**

将原目标、禁止事项、验收、计划版本和阶段产物做成结构化契约；阶段边界检查行为与契约是否一致，并记录偏离原因。允许变更但须由有权主体确认，而非 Agent 自改目标。

**得分点**

- 保留原始证据引用
- 用长任务回放测约束保持率

**追问**：用户中途改需求时如何更新契约？

**易错点**：仅把最初目标放进长上下文，不等于持续遵守。

**面经主题线索**：[INT-2bfa666e65](https://www.nowcoder.com/discuss/939623386806751232?sourceSSR=post)（B：曾定位公开原帖）；[INT-91419e91fb](https://www.nowcoder.com/discuss/938541088820695040?sourceSSR=post)（B：曾定位公开原帖）
