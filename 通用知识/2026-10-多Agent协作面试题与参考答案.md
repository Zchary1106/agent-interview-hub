## 79. 为什么这项任务值得拆成多个 Agent，而不是增加一个普通函数？

**题目 ID**：`Q-28ebed6ed8bd` · **编辑难度**：`hard`

**相关主题的报道公司（非逐题归属）**：快手

**参考答案**

只有子任务需要相对独立的推理、上下文、工具权限或可并行探索时才考虑 Agent；确定的数据转换优先函数或工作流节点。与单 Agent/函数方案比较质量、成本和故障面。

**得分点**

- 角色拆分不等于运行时隔离
- 先定义子任务契约

**追问**：两个角色都只在转发消息，应该保留吗？

**易错点**：不要把每个工具都包装成 Agent。

**面经主题线索**：[INT-065b4318d8](https://www.nowcoder.com/discuss/932315325276618752?sourceSSR=post)（B：曾定位公开原帖）

**答案机制资料**：[GRAPH：LangGraph: Workflows and agents](https://docs.langchain.com/oss/python/langgraph/workflows-agents)

## 80. 单 Agent 与多 Agent 的对照评测怎样做，才能避免比较口径不一致？

**题目 ID**：`Q-40eba6ec99a6` · **编辑难度**：`hard`

**相关主题的报道公司（非逐题归属）**：快手

**参考答案**

使用相同任务、模型能力、工具、数据及总 token/时间预算，单 Agent 也获得合理调优。多次运行比较最终验收、协作开销、违规和成本，并按任务复杂度分层。

**得分点**

- 计入调度与汇总调用
- 做去角色和去通信消融

**追问**：多 Agent 用了更多 token，公平比较如何设置？

**易错点**：增加预算后的高分不能归因于架构本身。

**面经主题线索**：[INT-065b4318d8](https://www.nowcoder.com/discuss/932315325276618752?sourceSSR=post)（B：曾定位公开原帖）

**答案机制资料**：[GRAPH：LangGraph: Workflows and agents](https://docs.langchain.com/oss/python/langgraph/workflows-agents)

## 81. 多 Agent 角色的职责与交付边界应该如何划分？

**题目 ID**：`Q-1c02f08a206d` · **编辑难度**：`medium`

**相关主题的报道公司（非逐题归属）**：快手、百度

**参考答案**

按可独立验证的交付物切职责，定义输入、约束、工具权限、输出 schema、证据、截止时间和失败上报。跨角色分歧由明确策略处理，而不是让多个角色无限互相讨论。

**得分点**

- 给每项子任务指定责任主体
- 明确共享资源和写入权

**追问**：两个 Agent 对同一结论冲突怎么办？

**易错点**：专家角色名称不能替代可验证职责。

**面经主题线索**：[INT-2706b0f563](https://www.nowcoder.com/discuss/931679347587444736?sourceSSR=post)（B：曾定位公开原帖）；[INT-c0e8c51474](https://mj.mianlingai.com/interview/baidu-ai-algorithm-first-second-round-2916318/)（C：仅聚合线索）

## 82. 子 Agent 超时或崩溃后，父 Agent 如何决定重试、接管还是终止？

**题目 ID**：`Q-886baa149e76` · **编辑难度**：`hard`

**相关主题的报道公司（非逐题归属）**：字节跳动、百度

**参考答案**

先判断是否可重试及外部效果是否未知，再按重试预算、截止时间和替代能力决定。能安全重放则重试，证据齐全可接管，未知副作用先对账，无法恢复则转人工或终止并报告部分结果。

**得分点**

- 接管从持久化边界开始
- 避免父子同时拥有写权限

**追问**：父 Agent 是否也可能在接管时重复写入？

**易错点**：子 Agent 失联不意味着它执行的外部动作没发生。

**面经主题线索**：[INT-2bfa666e65](https://www.nowcoder.com/discuss/939623386806751232?sourceSSR=post)（B：曾定位公开原帖）；[INT-c0e8c51474](https://mj.mianlingai.com/interview/baidu-ai-algorithm-first-second-round-2916318/)（C：仅聚合线索）

**答案机制资料**：[REPLAY：LangGraph Graph API: re-execution and idempotency](https://docs.langchain.com/oss/python/langgraph/graph-api)；[FENCE：How to do distributed locking, Martin Kleppmann](https://martin.kleppmann.com/2016/02/08/how-to-do-distributed-locking.html)

## 83. 多个 Agent 同时编辑同一文件时，如何防止覆盖并处理已有冲突？

**题目 ID**：`Q-04ff5aa53c0c` · **编辑难度**：`hard`

**相关主题的报道公司（非逐题归属）**：字节跳动、小米

**参考答案**

优先每任务独立分支或工作区、明确文件所有权，汇总时进行三方合并与测试。必须共享写入时用版本检查和串行提交，锁只保护受控临界区，冲突需语义审查。

**得分点**

- 不能让同一文件上的最后写入悄悄获胜
- 保留补丁和基线版本

**追问**：修改不同函数但破坏同一接口如何发现？

**易错点**：文件没出现文本冲突，不代表合并后行为正确。

**面经主题线索**：[INT-2bfa666e65](https://www.nowcoder.com/discuss/939623386806751232?sourceSSR=post)（B：曾定位公开原帖）；[INT-17e29773f1](https://www.nowcoder.com/discuss/931897509520109568?sourceSSR=post)（B：曾定位公开原帖）

**答案机制资料**：[FENCE：How to do distributed locking, Martin Kleppmann](https://martin.kleppmann.com/2016/02/08/how-to-do-distributed-locking.html)

## 84. 子 Agent 的结论是否需要中心节点审查，如何权衡瓶颈与一致性？

**题目 ID**：`Q-c1ba37332735` · **编辑难度**：`hard`

**相关主题的报道公司（非逐题归属）**：字节跳动

**参考答案**

高风险结论需要验证，但中心节点应做证据/约束检查和争议仲裁，而非重复全部推理。可以分层或分片审核低风险任务，对高风险与不一致结果集中复核。

**得分点**

- 校准审查器并保留分歧
- 测审查成本和漏检

**追问**：中心审查器与执行器共享同一误解怎么办？

**易错点**：再加一个 LLM Reviewer 不会自动带来独立正确性。

**面经主题线索**：[INT-340e4aa1be](https://mj.mianlingai.com/interview/bytedance-agent-2928966/)（C：仅聚合线索）

**答案机制资料**：未单列外部机制资料，属于编辑推导，须结合具体契约独立验证。

## 85. 多 Agent 共享什么状态、隔离什么状态，分别用什么机制保证？

**题目 ID**：`Q-e12d173a1abc` · **编辑难度**：`hard`

**相关主题的报道公司（非逐题归属）**：字节跳动

**参考答案**

共享任务契约、只读证据和经提交的产物；隔离私有消息、工具授权、临时文件和未提交状态。共享状态由单写者、事务版本或明确合并规则管理，不靠随意共享对话数组。

**得分点**

- 存储与缓存都带作用域
- 权限从可信上下文派生

**追问**：共同编辑计划时怎样避免读到半更新状态？

**易错点**：上下文隔离不是提示词里写一句“不要串任务”。

**面经主题线索**：[INT-bfd0fa0cf9](https://www.nowcoder.com/discuss/932407145864130560?sourceSSR=post)（B：曾定位公开原帖）

## 86. 多 Agent 同时产生部分结果时，怎样汇总为可解释的最终答案？

**题目 ID**：`Q-e748715014a1` · **编辑难度**：`hard`

**相关主题的报道公司（非逐题归属）**：携程

**参考答案**

要求结果包含结论、证据引用、置信边界、完成状态和未解决项；按实体/版本去重，校验事实冲突，按原验收合成答案。失败的分支要显式保留，不能伪装为完整结果。

**得分点**

- 不把多数投票等同于真实性
- 必要时回查权威来源

**追问**：三个 Agent 引用了同一错误网页，算三份证据吗？

**易错点**：简单拼接摘要可能隐藏矛盾和遗漏。

## 87. 多 Agent 协作与固定 workflow 的差异在哪里，哪些任务不应拆成 Agent？

**题目 ID**：`Q-c987f28fea04` · **编辑难度**：`hard`

**相关主题的报道公司（非逐题归属）**：百度

**参考答案**

工作流预定义控制流，Agent 在授权范围内根据反馈动态选动作；两者可以混合。确定性计算、高风险固定审批或短小转换通常不值得做成自治协作。

**得分点**

- 以需求不确定性而非团队角色名决定
- 解释可测试性与维护成本

**追问**：多 Agent 之间的交接是否仍需工作流控制？

**易错点**：多个模型节点不一定构成有意义的多 Agent 系统。

**面经主题线索**：[INT-1795ef9456](https://mj.mianlingai.com/interview/baidu-ai-test-development-second-round-2915577/)（C：仅聚合线索）

## 88. 用消息队列通信时，怎样处理子任务的异常状态并向上游反馈？

**题目 ID**：`Q-2ee0300eae8a` · **编辑难度**：`hard`

**相关主题的报道公司（非逐题归属）**：字节跳动

**参考答案**

为消息携带任务/尝试/操作 ID、状态版本和关联 ID；按至少一次投递考虑重复、乱序及超时。消费后幂等落状态，再发完成事件或用 outbox，超限进入可审计的死信/人工流程。

**得分点**

- 父层读取持久化状态而非只等一条消息
- 取消也要版本化

**追问**：消息发出但事务回滚怎么办？

**易错点**：消息队列的确认不等于外部业务动作恰好执行一次。

**面经主题线索**：[INT-2bfa666e65](https://www.nowcoder.com/discuss/939623386806751232?sourceSSR=post)（B：曾定位公开原帖）

**答案机制资料**：[REPLAY：LangGraph Graph API: re-execution and idempotency](https://docs.langchain.com/oss/python/langgraph/graph-api)；[STATE：LangGraph persistence](https://docs.langchain.com/oss/python/langgraph/persistence)
