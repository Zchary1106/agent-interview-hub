## 1. 一个系统要满足哪些运行时特征，才不只是把大模型接口包成聊天应用？

**题目 ID**：`Q-ad917a171e37` · **编辑难度**：`medium`

**相关主题的报道公司（非逐题归属）**：快手、网易

**参考答案**

关键不是是否用了框架，而是系统能围绕目标，根据环境反馈选择下一步动作，并管理行动后的状态与结果。固定流程也可含 Agent 节点，两者不是互斥标签。

**得分点**

- 解释目标、状态、工具、反馈和终止条件
- 用一个需要动态决策的实际任务对照单次问答

**追问**：什么场景根本不需要 Agent？

**易错点**：不要把循环调用模型就等同于可靠自治系统。

**面经主题线索**：[INT-6784717d92](https://mj.mianlingai.com/interview/netease-agent-development-first-round-2927708/)（C：仅聚合线索）；[INT-bbcb367aed](https://www.nowcoder.com/discuss/938541475766206464?sourceSSR=post)（B：曾定位公开原帖）

## 2. 把 ReAct 落成代码时，推理结果、工具动作和执行反馈分别是什么数据结构？

**题目 ID**：`Q-6d8d1d4df0eb` · **编辑难度**：`medium`

**相关主题的报道公司（非逐题归属）**：字节跳动、网易

**参考答案**

将一次决策表示为结构化动作提议：工具名、参数、调用 ID 或结束结果；运行时执行后生成关联该 ID 的成功/错误观察，再进入下一轮。可保存简短决策依据，不要求暴露或依赖模型私有思维链。

**得分点**

- 分离模型提议与真实执行
- 给状态、动作和观察定义可验证的类型

**追问**：怎样处理同轮多个工具调用？

**易错点**：不要把模型输出的“已执行”文本当作工具成功凭证。

**面经主题线索**：[INT-2bfa666e65](https://www.nowcoder.com/discuss/939623386806751232?sourceSSR=post)（B：曾定位公开原帖）；[INT-6784717d92](https://mj.mianlingai.com/interview/netease-agent-development-first-round-2927708/)（C：仅聚合线索）

## 3. 面对同一个业务需求，你怎样比较 ReAct 与先规划后执行两种方案？

**题目 ID**：`Q-304afc4d6cde` · **编辑难度**：`medium`

**相关主题的报道公司（非逐题归属）**：字节跳动、美团

**参考答案**

路径短且需边观察边选工具时，ReAct 易于迭代；步骤可分解且需审查成本或权限时，先规划再执行更可控。两者都需外部预算和失败恢复，可在执行中受控重规划。

**得分点**

- 用同一任务集比较成功率、成本、延迟与可解释性
- 说明规划错误如何反馈

**追问**：计划会不会在第一步就过时？

**易错点**：不能仅凭框架流行度决定架构。

**面经主题线索**：[INT-c233db2a53](https://www.nowcoder.com/discuss/938913714646929408?sourceSSR=post)（B：曾定位公开原帖）；[INT-77ca6f4ba2](https://mj.mianlingai.com/interview/meituan-fullstack-intern-first-round-2924710/)（C：仅聚合线索）

## 4. 请拆解 Harness 的模块边界，并说明哪些职责不应交给模型自己完成。

**题目 ID**：`Q-afcc85b30293` · **编辑难度**：`hard`

**相关主题的报道公司（非逐题归属）**：字节跳动

**参考答案**

Harness 可拆为输入/上下文构造、模型适配、工具执行、持久化状态、权限审批、资源预算、观测评测及恢复。模型可提出计划，权限判定、资金校验、超时和提交不能仅由它自行决定。

**得分点**

- 控制平面与模型决策分离
- 给每个模块说明输入、输出和失败边界

**追问**：哪些部分能替换，哪些必须统一？

**易错点**：一份长提示词不能代替运行时控制。

**面经主题线索**：[INT-2bfa666e65](https://www.nowcoder.com/discuss/939623386806751232?sourceSSR=post)（B：曾定位公开原帖）；[INT-c233db2a53](https://www.nowcoder.com/discuss/938913714646929408?sourceSSR=post)（B：曾定位公开原帖）

## 5. 模型运行时和工具运行时应如何解耦，才能替换不同厂商的模型？

**题目 ID**：`Q-dcf5a66c4160` · **编辑难度**：`hard`

**相关主题的报道公司（非逐题归属）**：字节跳动、百度

**参考答案**

模型层统一消息、工具定义、结构化动作、流事件、用量和错误；工具层统一鉴权、参数校验、执行回执与幂等。为不同厂商写能力适配器，保留不支持能力的显式降级。

**得分点**

- 协议统一不等于能力相同
- 模型升级须跑工具兼容和任务回归

**追问**：厂商不支持并行工具调用怎么办？

**易错点**：不要丢掉原始错误和用量，造成兼容层“假成功”。

**面经主题线索**：[INT-c233db2a53](https://www.nowcoder.com/discuss/938913714646929408?sourceSSR=post)（B：曾定位公开原帖）；[INT-15d1d6b299](https://www.nowcoder.com/discuss/938540748394217472?sourceSSR=post)（B：曾定位公开原帖）

## 6. 在你的项目中，为什么选择图式编排，而不是直接使用链式调用？

**题目 ID**：`Q-c90fa62b5d5c` · **编辑难度**：`medium`

**相关主题的报道公司（非逐题归属）**：携程、金蝶

**参考答案**

当任务有分支、循环、并行、审批与断点恢复时，图能显式表达状态转换；线性链路则更简单。LangGraph 的 checkpoint 不是任意代码行快照，节点重执行仍要考虑幂等。

**得分点**

- 先给出业务所需控制流
- 用复杂度和恢复测试证明选型

**追问**：一个节点内部崩溃后从哪里重跑？

**易错点**：不能声称使用图框架就自动获得业务 exactly-once。

**面经主题线索**：[INT-5906c726ec](https://mj.mianlingai.com/interview/ctrip-agent-dev-first-round-2916102/)（C：仅聚合线索）；[INT-85c5706c08](https://mj.mianlingai.com/interview/kingdee-agent-dev-first-round-2914937/)（C：仅聚合线索）

**答案机制资料**：[GRAPH：LangGraph: Workflows and agents](https://docs.langchain.com/oss/python/langgraph/workflows-agents)；[REPLAY：LangGraph Graph API: re-execution and idempotency](https://docs.langchain.com/oss/python/langgraph/graph-api)；[STATE：LangGraph persistence](https://docs.langchain.com/oss/python/langgraph/persistence)

## 7. 低代码节点编排与自主决策 Agent 各适用于什么任务，如何说明取舍？

**题目 ID**：`Q-b186a30ed291` · **编辑难度**：`medium`

**相关主题的报道公司（非逐题归属）**：网易

**参考答案**

固定、可枚举且高合规的链路更适合确定性编排；中间信息未知、需动态选工具的环节适合 Agent。可用工作流约束总体阶段，让 Agent 仅在授权节点内探索。

**得分点**

- 比较变化频率、失败代价与维护成本
- 先用更简单的方案作基线

**追问**：怎样防止 Agent 越过工作流阶段？

**易错点**：拖拽式编排也可能包含自主节点，不要按界面形态分类。

**面经主题线索**：[INT-6784717d92](https://mj.mianlingai.com/interview/netease-agent-development-first-round-2927708/)（C：仅聚合线索）

## 8. 多层 Agent 架构比单层方案多解决了什么问题，怎样证明额外复杂度值得？

**题目 ID**：`Q-644669edd5ed` · **编辑难度**：`hard`

**相关主题的报道公司（非逐题归属）**：字节跳动

**参考答案**

分层可隔离职责、上下文与工具权限，也引入通信、汇总和调度开销。只有同预算的单层对照实验显示质量或吞吐净收益，才证明层次值得保留。

**得分点**

- 按任务难度分桶比较
- 记录各层调用数、失败归因和成本

**追问**：去掉中间编排 Agent 会怎样？

**易错点**：增加 Agent 数量不是能力增长的证明。

**面经主题线索**：[INT-bfd0fa0cf9](https://www.nowcoder.com/discuss/932407145864130560?sourceSSR=post)（B：曾定位公开原帖）

## 9. 执行过程发现原计划不成立时，什么时候应该重新规划而非继续重试？

**题目 ID**：`Q-2f7d852b9804` · **编辑难度**：`medium`

**相关主题的报道公司（非逐题归属）**：字节跳动

**参考答案**

瞬时网络故障适合有界重试；目标变化、前提被否定、工具永久不可用或多次重试无进展时应重新规划。新计划要与原验收和权限对照，必要时请求用户确认。

**得分点**

- 区分可重试与需改计划错误
- 限制重规划次数和总预算

**追问**：重规划是否可以改变原验收条件？

**易错点**：不要用无限重规划掩盖不可完成的任务。

**面经主题线索**：[INT-5001eff5c7](https://mj.mianlingai.com/interview/bytedance-backend-intern-group-information-system-first-round-00e3488329c041c5a5a357c14ce138b4/)（C：仅聚合线索）

## 10. 将固定 workflow 改成 Skill 后，哪些约束仍需由确定性代码保证？

**题目 ID**：`Q-390ea2bbeafe` · **编辑难度**：`hard`

**相关主题的报道公司（非逐题归属）**：快手

**参考答案**

Skill 可以组织操作说明与可复用步骤，但身份、租户隔离、参数语义、审批、预算和状态转换仍由执行层强制。对关键动作实行默认拒绝，不能把文档约束当安全边界。

**得分点**

- 把自然语言规则转成可执行策略
- 为绕过路径设计负面测试

**追问**：模型忽略 Skill 时系统会发生什么？

**易错点**：“模型看过说明”不等于操作已获授权。

**面经主题线索**：[INT-bbcb367aed](https://www.nowcoder.com/discuss/938541475766206464?sourceSSR=post)（B：曾定位公开原帖）

## 11. 如何让 Agent 结束任务，避免把“继续思考”当成无限循环的理由？

**题目 ID**：`Q-897e02fc69c3` · **编辑难度**：`medium`

**相关主题的报道公司（非逐题归属）**：海康威视、网易

**参考答案**

同时定义业务完成、显式失败、等待外部输入和预算耗尽等出口；运行时监测重复动作、无进展、最大步数、截止时间及成本。完成需由可检查产物证明，而非只看模型说结束。

**得分点**

- 软终止与硬上限配合
- 超限保存状态和未完成原因

**追问**：如何判断两次动作其实没有进展？

**易错点**：最大步数只保证停下来，不保证做对。

**面经主题线索**：[INT-1f14c11bcf](https://mj.mianlingai.com/interview/hikvision-agent-first-round-2929422/)（C：仅聚合线索）；[INT-6784717d92](https://mj.mianlingai.com/interview/netease-agent-development-first-round-2927708/)（C：仅聚合线索）

## 12. 在业务层面，如何衡量一个 Skill 是否真正提升了任务完成效果？

**题目 ID**：`Q-c95c1cf24d36` · **编辑难度**：`hard`

**相关主题的报道公司（非逐题归属）**：快手

**参考答案**

冻结模型、样本、工具版本和预算，比较有/无 Skill 的任务成功率、违规率、成本和延迟。还要区分是文档内容、工具改进还是执行约束带来收益。

**得分点**

- 按业务验收计分
- 加入失败与边界场景，报告样本量

**追问**：Skill 内容变长是否反而降低成功率？

**易错点**：不要拿几个演示案例替代对照评测。
